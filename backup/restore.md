# Disaster Recovery Runbook

Черновой runbook для восстановления системы после потери VPS или хранилища.
Ниже нет автоматических destructive-команд; все шаги должны выполняться вручную и с проверкой.

## 1. Подготовка нового VPS

- Поднять новый VPS с нужной ОС и сетевым доступом.
- Создать пользователя `katrin`, если он отсутствует.
- Проверить доступ по SSH.
- Проверить наличие дискового пространства под `/srv/backups` и рабочие данные.

## 2. Установка Docker и Docker Compose

- Установить Docker.
- Установить Docker Compose.
- Проверить доступность `docker` и `docker compose`.

## 3. Клонирование `the-hub-infra`

- Клонировать репозиторий `the-hub-infra`.
- Перейти в рабочую копию.
- Проверить, что структура `backup/` на месте.

## 4. Восстановление секретов

**Внимание:** секреты не должны храниться в Git.

- Восстановить `.env`-файлы и другие секреты из доверенного источника.
- Проверить права доступа.
- Проверить, что значения соответствуют целевому VPS.

## 5. Подключение restic repository

- Настроить `RESTIC_REPOSITORY`.
- Настроить `RESTIC_PASSWORD_FILE`.
- Проверить, что репозиторий доступен для чтения.
- Не выполнять инициализацию или перезапись репозитория без явного подтверждения.

## 6. Восстановление PostgreSQL globals

**Внимание:** перед применением убедиться, что целевой кластер готов.

- Получить глобальные роли и привилегии из резервной копии.
- Восстановить globals через `pg_dumpall --globals-only`-совместимый процесс.
- Проверить владельцев и права доступа.

## 7. Восстановление PostgreSQL databases

**Внимание:** операции восстановления могут перезаписывать данные.

- Создать нужные базы данных.
- Восстановить логические дампы по каждой базе.
- Проверить подключения приложений.

## 8. Восстановление SQLite

**Внимание:** перед заменой файлов баз данных убедиться, что сервис остановлен или работает на копии.

- Разместить восстановленные SQLite-файлы в целевых путях.
- Проверить права доступа и владельца файлов.
- Выполнить проверку целостности базы.

## 9. Восстановление файловых данных

**Внимание:** восстановление файловых данных может перезаписать текущие каталоги.

- Подготовить целевые директории.
- Восстановить файловые данные из `restic`.
- Проверить права доступа, владельца и содержимое.

## 10. Запуск сервисов

- Запустить Docker Compose stack'и по порядку.
- Проверить логи стартующих контейнеров.
- Не переходить к следующему шагу, пока критичные сервисы не поднялись.

## 11. Проверка приложений

- Проверить доступность основных веб-интерфейсов.
- Проверить авторизацию и ключевые пользовательские сценарии.

## 12. Проверка Grafana

- Открыть Grafana.
- Проверить datasources и дашборды.
- Проверить, что provisioning применился корректно.

## 13. Проверка Uptime Kuma

- Открыть Uptime Kuma.
- Проверить, что записи мониторинга доступны.
- Проверить актуальность статусов.

## 14. Проверка Docker Registry

**Внимание:** тестовый `docker pull` должен использовать безопасный тестовый образ.

- Выполнить тестовый `docker pull` из registry.
- Проверить успешную аутентификацию.
- Проверить, что образ скачивается без ошибок.

## 15. Финальный checklist

- [ ] PostgreSQL globals восстановлены
- [ ] PostgreSQL databases восстановлены
- [ ] SQLite восстановлены
- [ ] Filesystem данные восстановлены
- [ ] Секреты возвращены
- [ ] Сервисы запускаются
- [ ] Grafana проверена
- [ ] Uptime Kuma проверена
- [ ] Docker Registry проверен
- [ ] Тестовое восстановление зафиксировано
