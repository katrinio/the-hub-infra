Use simple, human-readable logging.

Log only important steps and state changes. Do not log every command or internal detail.

Each log entry should:
- be one short line;
- start with a timestamp generated by the script;
- clearly describe what happened;
- include important values when useful (sizes, durations, counts);
- distinguish INFO, WARN, and ERROR messages.

Example:

```text
2026-07-15 04:30:01 INFO  Starting Docker build cache cleanup
2026-07-15 04:30:02 INFO  Build cache before cleanup: 17.4 GiB
2026-07-15 04:30:12 INFO  Build cache after cleanup: 684 MiB
2026-07-15 04:30:12 INFO  Reclaimed: 16.7 GiB
2026-07-15 04:30:12 INFO  Prometheus metrics updated
2026-07-15 04:30:12 INFO  Cleanup completed successfully
```

The log should make it easy to understand what happened by reading it from top to bottom.

- The systemd service must send stdout and stderr to journald.

- Add useful labels:
  - job="docker-cache-cleanup"
  - service="docker-build-cache-prune"
  - host=<current hostname>
- Do not add cache size values as Loki labels. Keep them inside the log message.
- Add a Grafana dashboard or panel with:
  - all cleanup logs;
  - ERROR logs only;
  - the latest successful cleanup.
